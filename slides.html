Developer advocacy at LiveKit

a working plan by YK

The big picture

  • Real-time audio and video are hard: latency, packet drops, reconnection
  • Demand is exploding: OpenAI and ChatGPT today, other LLM companies next
  • Then video and physical AI: robots stream the same kind of data
  • LiveKit solves this on both sides: open source stack + operated global infra

My approach: become the expert in public

  • Create content: blog posts, videos, talks
  • Talk to customers and potential customers
  • Learn and improve what exists: docs, blog posts, materials
  • Build deep expertise in real-time audio, video, and sensor data
  • Use that expertise to speak, answer questions, and host events confidently

Start in San Francisco and expand

or global content first, then SF. both loops feed each other
  • Present and record talks in San Francisco
  • Turn each talk into a video, a blog post, a Reddit post
  • Different formats reach different audiences, both people and AI
  • Proven playbook from Sourcegraph: luma.com/sourcegraph

30 / 90 / 360 days

First 30 days

  • Learn as much as possible
  • Improve existing processes and materials
  • Join existing events
  • Start applying to speak, without overcommitting

First 90 days

  • Set the direction
  • Try a few different things and measure what works best
  • Hackathons? Speaking events? Sourcegraph-style meetups?

First 360 days

  • Scale the programs that work
  • Follow the data: YouTube? Reddit? Search and AI optimization? Where do people come from?
  • Build the flywheel: customers → case studies → talks → videos → more developers
  • Example: "How OpenAI achieved real-time voice latency at scale" as a conference talk

Logistics

  • Based in Vancouver
  • Travel to San Francisco up to twice a month
  • Same model I ran successfully at Sourcegraph
